Mini Query Language

This document defines a small query language over the Mini Data Model. It is intentionally limited to literals, object and array constructors, arithmetic, boolean logic, value comparison, restricted FLWOR expressions, instance tests, comma expressions, static function calls, and conditionals.

Abstract

The Mini Query Language is an expression language whose values are strings, numbers, booleans, null, objects, and arrays. It is a small subset inspired by XQuery 3.1, suitable for spec-driven student implementations.

1 Introduction

A query consists of one expression. Evaluating an expression produces a sequence of values. A value is one of the six value kinds defined by the Mini Data Model.

2 Conformance

The keywords must, must not, should, and may are to be interpreted as described in RFC 2119.

A conforming implementation must implement every expression kind in this specification and must not require any feature excluded in Section 17.

3 Data Model

The only values are strings, numbers, booleans, null, objects, and arrays. Expression results are sequences of zero or more values. A sequence is not a value and cannot appear inside an object or array.

4 Errors

An implementation must report a static error when an expression is not syntactically valid or refers to an unbound variable or unknown function. It must report a dynamic error when an operation receives a value of the wrong kind.

5 Grammar Summary

Expr          ::= CommaExpr
CommaExpr     ::= ExprSingle ("," ExprSingle)*
ExprSingle    ::= FLWORExpr | IfExpr | OrExpr
FLWORExpr     ::= InitialClause Clause* WhereClause? "return" ExprSingle
InitialClause ::= ForClause | LetClause
Clause        ::= ForClause | LetClause
ForClause     ::= "for" VarRef "in" ExprSingle
LetClause     ::= "let" VarRef ":=" ExprSingle
WhereClause   ::= "where" ExprSingle
IfExpr        ::= "if" "(" Expr ")" "then" ExprSingle "else" ExprSingle
OrExpr        ::= AndExpr ("or" AndExpr)*
AndExpr       ::= NotExpr ("and" NotExpr)*
NotExpr       ::= "not" "(" Expr ")" | ComparisonExpr
ComparisonExpr ::= AdditiveExpr (ValueComp AdditiveExpr | "instance" "of" TypeName)?
AdditiveExpr  ::= MultiplicativeExpr (("+" | "-") MultiplicativeExpr)*
MultiplicativeExpr ::= UnaryExpr (("*" | "div" | "mod") UnaryExpr)*
UnaryExpr     ::= ("+" | "-")* PrimaryExpr
PrimaryExpr   ::= Literal | VarRef | ObjectConstructor | ArrayConstructor
                | FunctionCall | ParenthesizedExpr
ValueComp     ::= "eq" | "ne" | "lt" | "le" | "gt" | "ge"
TypeName      ::= "string" | "number" | "boolean" | "null" | "object" | "array"
Literal       ::= StringLiteral | NumberLiteral | BooleanLiteral | NullLiteral
BooleanLiteral ::= "true" | "false"
NullLiteral   ::= "null"
VarRef        ::= "$" VarName
FunctionName  ::= VarName
ObjectConstructor ::= "{" (StringLiteral ":" ExprSingle
                      ("," StringLiteral ":" ExprSingle)*)? "}"
ArrayConstructor  ::= "[" (ExprSingle ("," ExprSingle)*)? "]"
FunctionCall  ::= FunctionName "(" (ExprSingle ("," ExprSingle)*)? ")"
ParenthesizedExpr ::= "(" Expr? ")"

6 Literals

Literal expressions produce one atomic value. The literal kinds are string, number, boolean, and null, as given by the grammar. Boolean literals are spelled true and false; the null literal is spelled null. These spellings are case-sensitive and match JSON.

String literals use JSON string syntax, including its quoting and escape rules. Number literals use JSON number syntax without a leading sign; unary plus and minus are handled by the unary-expression grammar. A number literal is converted to binary64 as described in the Mini Data Model. A literal whose value is not finite in binary64 is a static error.

Literal Value
String literal A string value.
Number literal A number value.
Boolean literal The boolean value true or false.
Null literal The null value.

7 Constructors

7.1 Object Constructors

An object constructor produces one object. Each pair name must be a string. Each pair value expression must produce exactly one value. Duplicate pair names are a dynamic error.

7.2 Array Constructors

An array constructor produces one array. Each member expression must produce exactly one value. The order of member expressions is the order of members in the array.

8 Variables

A variable reference returns the sequence bound to that variable. A A VarName starts with an ASCII uppercase letter, lowercase letter, or underscore. Subsequent characters may be ASCII letters, digits, or underscores. A variable reference is spelled $ immediately followed by its VarName; whitespace is not allowed between them. Variables are introduced only by for and let clauses. Referring to an unbound variable is a static error.

9 Arithmetic

Arithmetic operators are addition, subtraction, multiplication, division, and remainder. Each operand must be a sequence containing exactly one number. The result is one number rounded to binary64 using round-to-nearest, ties-to-even. Underflow follows IEEE 754. A result that is not finite is a dynamic error.

Division (div) is true division. Remainder (mod) uses floor division: for operands a and nonzero b, a mod b is a - floor(a / b) * b. The result is rounded to binary64 as described above. A nonzero remainder has the sign of the divisor and a magnitude less than the divisor's magnitude. A zero divisor is a dynamic error.

10 Logic

The logical operators are and, or, and not. Each operand must have an effective boolean value. The result is one boolean.

The effective boolean value of an empty sequence is false. The effective boolean value of a single boolean is that boolean. All other effective boolean values are dynamic errors.

Logical operands are evaluated from left to right. The operands of and and or are both evaluated and both effective boolean values are checked, even when the left operand alone determines the result. These operators do not short-circuit.

11 Value Comparison

Value comparison operators are eq, ne, lt, le, gt, and ge. Each operand must be a sequence containing exactly one atomic value. Equality and inequality are defined for all atomic values. Ordering comparisons are defined only for two numbers or two strings.

12 FLWOR Expressions

A for expression binds a variable once for each value in its input sequence and concatenates the results of evaluating its return expression.

A let expression binds a variable to the entire sequence produced by its binding expression and evaluates its return expression once.

A where clause filters a tuple. The tuple is kept only when the where expression has the effective boolean value true.

13 Instance Tests

An instance test has one of the six builtin type names: string, number, boolean, null, object, or array. The input sequence must contain exactly one value. The result is true if that value has the named kind, otherwise false.

14 Function Calls

A static function call names a function known during static analysis. A FunctionName uses the same syntax as VarName. Arguments are evaluated from left to right and passed as sequences. Calling an unknown function is a static error.

This specification does not define a standard function library. A conforming implementation may provide implementation-defined functions.

15 Conditional Expressions

A conditional expression evaluates its test expression. If the effective boolean value is true, it evaluates the then expression; otherwise, it evaluates the else expression. Only the selected branch is evaluated.

16 Serialization

A nonempty result sequence is printed as one serialized value per line, in sequence order. An empty result sequence is printed as (). Each value is serialized as compact JSON, with no insignificant whitespace. Strings and object pair names are quoted and escaped according to JSON string rules. Arrays preserve member order. Pairs in an object are sorted by pair name in ascending Unicode scalar-value order. Numeric spellings must denote the same binary64 value when read back as a number.

17 Excluded Features

This language has no modules, declarations, namespaces, XML nodes, path expressions, attributes, comments, processing instructions, text constructors, string constructors, dynamic function calls, inline functions, higher-order functions, maps distinct from objects, lookup operators, order by, group by, count, window clauses, quantified expressions, switch, typeswitch, cast, castable, treat, try/catch, validation, updates, collation, or schema awareness.

This specification is intended to pair with the Mini Data Model. The data model defines what values exist; this language defines a small set of ways to construct, combine, test, and select those values.

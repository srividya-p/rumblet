Mini Data Model

This document defines a small data model for use in teaching spec-driven development. It defines only values and their properties. It does not define any language, type system, schema system, storage system, or interchange format.

Abstract

The Mini Data Model defines the set of values that may exist in a conforming implementation. The model contains six kinds of values: strings, numbers, booleans, null, objects, and arrays.

1 Introduction

A data model defines what information exists independently of how that information is represented outside the model. This specification intentionally contains only value definitions.

2 Conformance

The keywords must, must not, should, and may are to be interpreted as described in RFC 2119.

A conforming implementation must represent every value as exactly one of the six value kinds defined in this specification.

3 Terminology

Term Meaning
Value An item of information in the data model.
Atomic value A string, number, boolean, or null value.
Container value An object or array value.
Pair A string name and value contained by an object.
Member A value contained by an array.

4 Values

The universe of values consists only of strings, numbers, booleans, null, objects, and arrays. No other value kind exists in this data model.

Kind Description
String A finite sequence of Unicode scalar values.
Number A finite IEEE 754 binary64 floating-point number.
Boolean One of the two truth values true and false.
Null The single value representing absence.
Object An unordered collection of pairs.
Array An ordered sequence of members.

5 Atomic Values

5.1 Strings

A string is a finite sequence of Unicode scalar values. Strings have length. The length of a string is the number of scalar values in the sequence.

Two strings are equal if they contain the same scalar values in the same order.

5.2 Numbers

A number is a finite IEEE 754 binary64 floating-point number. The term “double precision” refers to binary64, not decimal floating point. A value converted to binary64 is rounded to the nearest representable value; exact halfway cases are rounded to the value whose significand is even. Underflow follows IEEE 754, including subnormal values and rounding to zero. Positive and negative zero compare equal. Infinity and NaN are not values in this data model.

Two numbers are equal if they represent the same numeric value.

5.3 Booleans

A boolean is one of two values: true or false. The two boolean values are distinct.

5.4 Null

Null is a single atomic value. It has no object pairs, array members, name, length, numeric value, or truth value defined by this specification.

6 Objects

An object is an unordered collection of pairs. Each pair has a string name and a value. Within one object, pair names must be unique.

The order of pairs in an object is not significant. Two objects are equal if they have the same pair names and each corresponding pair has an equal value.

7 Arrays

An array is an ordered sequence of zero or more values. Each member has a position. Positions are significant.

Two arrays are equal if they have the same length and equal members at every corresponding position.

8 Nesting

Objects and arrays may contain any value, including other objects and arrays. This specification defines no maximum depth or size. An implementation may impose resource limits.

9 Identity

Values have no identity separate from their kind and content. If two values have the same kind and equal content, they are the same value for purposes of this data model.

10 Excluded Features

This data model has no nodes, attributes, namespaces, documents, comments, processing instructions, functions, maps distinct from objects, tuples, dates, times, binary values, schemas, annotations, references, pointers, or user-defined value kinds.

This specification is intended to pair with the Mini Query Language. This data model defines what values exist; the query language defines a small set of ways to construct, combine, test, and select those values.
